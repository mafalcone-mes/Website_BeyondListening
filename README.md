# Beyond Listening

A public archive of personal stories tied to songs. Built with Next.js 16 (App Router, TypeScript) and Supabase (Postgres, Auth, Storage, Row Level Security).

- **Site owner / non-developers:** read **[START_HERE.md](START_HERE.md)**.
- **Going online later:** [GOING_ONLINE.md](GOING_ONLINE.md).
- **Original brief:** [docs/PLANNING_PROMPT.md](docs/PLANNING_PROMPT.md).

## Developer quick start

Requirements: Node.js ≥ 20.9 and Docker Desktop.

```bash
npm run local:start      # same as the double-click launcher: Docker check, supabase start, .env.local, build, run
npm run local:stop       # stop site + local Supabase (data kept)

# day-to-day development
npx supabase start       # local Postgres/Auth/Storage + Mailpit (http://127.0.0.1:54324)
npm run dev              # http://localhost:3000 (needs .env.local; run local:start once to create it)
npm run lint && npm run typecheck
npx supabase test db     # Row Level Security tests (supabase/tests/database)

# data
npm run backup           # backups/<date>/ : data-only SQL dump (public + auth) + every Storage file
npm run restore          # list backups;  npm run restore -- <name>  REPLACES local data
npm run maintenance      # retention purges, salt rotation, email retries (same as /api/cron/daily)

# phone on the same Wi-Fi (HTTPS is required for the microphone)
npm run phone            # prints https://<lan-ip>:3000 ; accept the certificate warning on the phone
```

Local admin: `admin@beyond-listening.local` (created by the launcher; magic links arrive in Mailpit).
Override with `ADMIN_EMAIL` in `.env.local`.

### How the browser reaches Supabase
The browser never talks to Supabase directly. Signed upload URLs, signed audio URLs and covers are rewritten to
`/sb/...` (`src/lib/supabase/browser-url.ts`), which `next.config.ts` proxies to Supabase. One origin means it
works from phones on the LAN and keeps the CSP tight.

### Privacy-relevant external requests (browser)
Deezer/Apple CDNs (previews, artwork) and Hugging Face (one-time Whisper model download). The ONNX runtime is
self-hosted in `public/onnx` (copied at `postinstall`). `MUSIC_PROVIDER=mock` removes the music services entirely.

## Where things live

| Path | What |
|---|---|
| `src/styles/tokens.css` | **All design tokens** (colors, type, spacing, radius, shadow, motion, dark mode) |
| `src/styles/fonts.ts` | Font families (one line per family) |
| `src/app/globals.css` | Tailwind v4 wiring. The default theme is disabled, so only tokens exist |
| `src/content/copy.ts` | All UI wording |
| `src/components/{ui,patterns,sections}` | Presentational components (props only, no data access) |
| `src/features/*` | Data access, server actions, containers |
| `src/lib/*` | Supabase clients, env, providers (music, email, storage) |
| `supabase/migrations`, `supabase/seed.sql` | Database schema and fictional sample data |
| `scripts/launcher.mjs` | Cross-platform one-click launcher (built-ins only) |
| `scripts/bootstrap-node.{sh,ps1}` | Downloads a portable Node into `.runtime/` if needed |
| `/styleguide` | Designer workbench: every token and component state |

## Rules
- No raw colors or pixel values in components. Use tokens (see `src/app/globals.css`).
- `.env*` is never committed. Locally it's generated by the launcher.
- `src/lib/supabase/admin.ts` (secret key) is server-only.
